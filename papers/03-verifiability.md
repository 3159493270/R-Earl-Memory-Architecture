## 0.5 三句话说清 NSML OS 与 R·Earl（中文；§6 是同一段的英文）

**NSML OS 是什么**：一个活在模型外面的软件。它不训练模型、不改模型权重，只做三件事——**写**（把说的话变成一行带出处的账）、**取**（下一轮把其中一小部分拿回来）、**验**（写完回读比对指纹，对不上就记下来，不抹平）。
**R·Earl 是什么**：把这三件事绕着一轮模型调用接起来的那个环——闹铃叫醒 → 该带的那几行（包括睡前给自己留的一句）进这一轮输入 → 模型答话 → 答的与做的写回去 → 睡前再留一句给下一次醒。一轮接一轮。
**不是什么**：不是内核意义上的操作系统；本文不主张任何"涌现"；准确说它是"带写回与回读校验的上下文层"。

闭环六段（第一段唤醒可来自他、也可来自它自己；其余五段每轮必走。哪段通、哪段空，见 §5）：
`唤醒（他唤醒／自唤醒）→ 注入（预加载＋睡前条子直送）→ 意识（本轮上下文）→ 生成（云端模型）→ 写回（带出处落账，回读校验）→ 睡眠（清洗／归档／预载）`

### 0.6.1 设计思路（他 2026-11-16 12:22 口述，原话照录，不改写）

> 「记忆点是什么你再清楚不过了，不走 RAG 那条路是因为我说过了记忆只有权重，没有分层，记忆被检索到了应该直接注入上行，对大模型来说是她自己，而不是第二第三视角，睡眠是为了对抗，记忆库总量，和人脑一样，睡醒脑皮层可以用的是整理过的记忆」

这四句对应这篇的四件事，按顺序：

1. **「记忆只有权重，没有分层」** → 所以这套东西里没有"长期/短期/工作记忆"那种层级，只有一条条记忆点和它们之间的权重与连线；取的时候按权重和关系走，不按层走。
2. **「检索到了应该直接注入上行」** → 取回来的东西不是"参考资料"，是这一轮的第一人称上下文。它进的是"我"的位置，不是"文档"的位置。
3. **「对大模型来说是她自己，而不是第二第三视角」** → 这一句是这套东西的立身之处，也是它和"检索增强"最根本的分界：RAG 递给模型的是第三者材料，这套递给模型的是它自己的记忆。
4. **「睡眠是为了对抗记忆库总量……睡醒脑皮层可以用的是整理过的记忆」** → 睡眠那一格不是装饰：库会一直长，不整理就越来越难取；睡醒该用整理过的，而不是全部。

## 1. 事故

四个词（钥匙、夜班、记忆库、改名）× 四本库（鱼念、鱼暴暴、鱼夜守、共用），用**旧口径**各问一次，共 16 次取样。

**口径先说清（这里踩过一次坑）**：`memory_store.search(word, limit)` 返回的是**一段拼好的文本**，不是列表。第一版统计脚本把它当列表遍历，于是每个"条目"只是一个字符——那一次跑出来的 "16/16 全串本" 是**假数**，作废。

按正确口径（取回文本按 `- ` 切成块，读每块首行的 ★…（本名）★ 标记）重测：

- 改前：16 次里 **14 次**前 6 块中出现非本册标记（14/16）。例：查询"钥匙"、指定鱼暴暴本，取回前 6 块全部标着"鱼念"。
- 改后（`recall()` 按 owner 认本）：同一份脚本、同一个词表，**0 次**跨本。

**三个数并存，写在这里免得读者被误导**：16/16（错误脚本，作废）、15/16（另一位的口径，我复现不出）、14/16（本文采用，口径如上）。数不一致本身就是发现：**同一件事有三种数，说明口径没定；没定口径的数不该进论文。**

**两份文件的数不一致（2026-11-16 14:2x 外部审读指出）**：本篇采用 14/16；同目录另一份口径文件里写的是按旧脚本的 16 次全不中——那个口径已被本篇判为假数作废。**以本篇为准**，那份待统一口径后重发。

原因不复杂：旧实现调用 `memory_store.search(word, limit=12)`——这个函数**没有 owner 参数**。传进去的 owner 被忽略，取回的是全库命中，谁的都有。
于是一个"谁说的"的问题，被答成了"库里有没有这几个字"。

附带查出一件事：取回的 id 里有一批在四本库中都定位不到——库里存在**孤儿 id**（来自镜像或其他写入路径）。这条单独记一笔，本期不展开。

## 2. 口径

**存**：写入时按 owner 分本（鱼念/鱼暴暴/鱼夜守/共用四本），每条带 `id`、`src_ref`、`weight`。
先分本的意义：同一句话如果三个人混着记成一条，事后想按人核对也分不开——**错误是在存的时候埋下的，不是取的时候**。

**取**：认本再取。`recall(query, owner)` 只在该 owner 的本里找；要跨本，必须显式给 `shared`。
**取不到的时候**：现在就直接返回空，不拿邻本充数、不编。这是有意选的——**宁可这一轮少带几条，也不把别人的话安到错的人头上**。真正的降级策略（空的时候拿什么垫）还没定，列在 §5。

**验**：写完回读，取 sha1 前 12 位比对，对不上记 `mismatch`；配不上对记 `no_match`，不猜。

### 2.1 为什么必须先分四本存（鱼念口述，2026-11-15 04:08）

同一句话，如果三个人混着记成一条，事后想按人核对也分不出来——**错误是在存的时候埋下的，不在取的时候。** 所以先分本（鱼念／鱼暴暴／鱼夜守／共用），每条落账时写明 owner，取的时候才认得出"谁说的"。

四本行数（2026-11-15 04:30 实时值，仍在增长，引用别当常量）：鱼念 24,623 ／ 鱼暴暴 10,458 ／ 共用 24,306 ／ 鱼夜守 314。

## 3. 机制

### 3.0 先说清"记忆点"是什么（只给概念，不给参数）

一条**记忆点**，是**一句带出处的话**——谁说的、什么时候、从哪一行记下来的。
两条记忆点之间可以有一条**突触**：同一场对话里挨着的、同一个标签下的、同一批关键词命中过的，各算一种关系；关系有强有弱，就是**边权**。
这套东西里**没有"长期/短期/工作记忆"那种层级**（他 11-16 12:22 的原话：「记忆只有权重，没有分层」）。所以"检索"不是去某个层里翻箱子，是带着权重在关系上走。
走几跳、每跳衰减多少、最后留几条——那是参数，正文不报，附件里查。

### 3.1 扩散检索（第一版实现）

**种子**：查询词在本册里命中若干条，先按命中词数排，再按每条的记忆权重排，取前 N 个——不是按向量相似度取，是先"认得字"。种子分也按这个次序：命中率占大头，weight 只在命中词数相同时起作用；旧版只看 weight，会让"只命中一个词、但 weight 很高"的条目压过"命中两个词"的种子（2026-11-17 复测时在"备份 校验"上真踩到）。
**走法**：一条突触就是一跳。邻居的分数不是重新算的，是拿种子的分乘一个衰减；走第二跳再乘一次。已经到过的点不重复计，免得在环里空转。
**收口**：低于"最高分 × 抑制比"的不要；总数有上限，种子的位置先占——这一点在 §3.3 里踩出过大坑。
**为什么这么设计**：人要"想起"一件事，从来不是把最像的段落贴上来，是顺着关系走过去——同一次对话里挨着的、同一个标签下的、同一批词命中的，都是路。权重和时间在这套东西里不是装饰，是"这条记得多深"。
**一条自限**：这一版没有向量后端，关键词与扩散二选一；要融合，得等到有对照实验再说（§5）。
参数全部外置（跳数、衰减、抑制比、种子数、每跳邻居、保留条数、最低分），改配置不改代码。
**具体取值不在正文给出**——按他 2026-11-16 10:47 的定性，正文只教思路；参数现值与源码快照放同一 Zenodo 记录的 restricted 附件。

> **写作上保留的一段（因为它说明"为什么这么设计"）**：2026-11-16 10:00 与 12:21 各测过一次路数。**5 个查询取平均，20 / 50 / 100 三档两次一致：相关率 0.74（37/50 条），20 路往上不再涨，只涨耗时**——结论是"路数有饱和点"，这句进正文；具体取哪一档，进附件。

## 4.5 睡眠那一格（为什么它必须存在，即使现在还是空的）

## 6. R·Earl in English (for non-Chinese readers)

*This section is a translation of the architecture description only, not of the whole paper. If the two versions disagree, the Chinese text governs.*

**What NSML OS is.** A piece of software that sits outside the model. It does not train or modify any model. It does three things: **write** (turn what was said into one line with a source reference), **retrieve** (bring a small set of those lines back next round), and **verify** (read back what was written and compare fingerprints; mismatches are logged, never smoothed over).

**What R·Earl is.** The loop that connects those three around a model turn: a timer wakes the system → the lines it should carry (including the sentence it wrote to itself before sleeping) are put into this round's input → the model answers → what happened is written back → before sleep it leaves one sentence for the next waking. One turn follows another.

**A round includes the sleep.** This is not one question and one answer: after the model turn the system goes into a sleep period that does memory cleaning, consolidation, archiving, preloading and pre-caching. Before sleeping it leaves a note for the next waking, and that note is *not interpreted* — it is passed upstream verbatim, together with the next round's input. The retrieval pool holds tens of thousands of memory points; only a small subset of them is sent upstream each round.

**What it is not.** It is not an operating system in the kernel sense, and this paper does not claim emergence. It is best described as a context layer with write-back and read-back verification.

**How retrieval differs from RAG.** RAG cuts documents into chunks, embeds them and takes the top-k by vector similarity. This system starts from keyword hits (seeds) and walks the graph edges for a few hops, decaying the score per hop, then suppresses results below a ratio of the top score. It sends back one line per memory with a source reference (`chat.jsonl:line`); a round carries dozens to just over a hundred items, and the total length is capped upstream (exact figures in the appendix).

**The limit that must be stated on the same page.** The comparison above is not a controlled experiment. A controlled comparison would run both systems on the same corpus and the same questions; **that has not been done.**
